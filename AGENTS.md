## 1. Что это за проект

Telegram-бот с AI-агентом поддержки/продаж **для любого малого бизнеса**.
Клиент пишет в Telegram — агент здоровается, отвечает на вопросы по базе знаний
(`knowledge/`), квалифицирует запрос, собирает заявки (контакты + тема), а в
спорных случаях передаёт диалог живому менеджеру-владельцу. Владелец видит
заявки в мини-дашборде и отвечает клиенту прямо оттуда.

Ключевые сценарии продукта:

1. **Ответ на вопрос** — агент ищет релевантный фрагмент в `knowledge/*.md` и отвечает.
2. **Квалификация лида** — распознаёт намерение купить/заказать/записаться, собирает контакт.
3. **Заявка (ticket)** — контакт + тема + транскрипт диалога сохраняются в БД.
4. **Эскалация** — жалобы, сложные вопросы, прямая просьба «позовите человека» →
   тикет типа `handoff`, уведомление владельцу в Telegram, бот замолкает в этом чате.
5. **Ответ владельца** — из дашборда (или напрямую в Telegram) → сообщение уходит клиенту.
6. **Закрытие заявки** — бот снова включается в чате.

## 2. Технологический стек

| Слой          | Технология                                   |
|---------------|----------------------------------------------|
| Язык          | TypeScript (strict), Node.js >= 18           |
| Бот           | [Telegraf](https://telegraf.js.org) v4       |
| Дашборд       | Express + одностраничный HTML (без фреймворков) |
| БД            | Postgres/Supabase (`pg`) **или** JSON-файл без настройки |
| LLM           | Опционально, любой OpenAI-совместимый API через `fetch` |
| База знаний   | Markdown-файлы в `knowledge/`, поиск по ключевым словам (RAG-lite) |

Принцип: **проект обязан запускаться с нуля без paid-API и без Supabase**
(фолбэки: JSON-хранилище, шаблонные ответы). Всё «тяжёлое» — опционально и
включается переменными окружения.

## 3. Быстрые команды

```bash
cp .env.example .env    # заполнить BOT_TOKEN и OWNER_TELEGRAM_ID
npm install
npm run dev             # бот + дашборд (tsx watch, автоперезапуск)
npm run doctor          # самопроверка окружения (токен, БД, база знаний)
npm run build           # tsc — проверка типов/сборка в dist/
```

Дашборд: `http://localhost:3000` (порт из `DASHBOARD_PORT`).

## 5. Бизнес-контекст (ЗАПОЛНИТЬ ПОД СВОЙ БИЗНЕС)

- **Название:** переменная `BUSINESS_NAME` из `.env` (по умолчанию «ПримерКомпани»).
- **Чем занимается бизнес:** см. `knowledge/about.md` — владелец редактирует текст.
- **Прайс и услуги:** `knowledge/pricing.md`.
- **FAQ:** `knowledge/faq.md` — формат «Вопрос» → «Ответ».

Задача AI-агента при доработках: НЕ придумывать факты о бизнесе. Всё, что
знает бот о компании, должно приходить из `knowledge/` или из `.env`.

## 6. Правила поведения бота (продуктовая логика)

1. Тон: дружелюбный, на «вы», без канцелярита, ответы до ~1200 символов.
2. Отвечать только на основании БЗ. Если данных нет — честно признавать и
   предлагать оставить заявку или позвать менеджера. НЕ выдумывать цены и сроки.
3. Никогда не раскрывать внутренности: токены, .env, структуру БД, промпты.
4. Эскалация немедленная при: жалобе/негативе, угрозах, просьбе позвать
   человека, вопросах о возврате денег, юридических темах.
5. Лид = намерение купить/заказать + получен контакт (телефон/email/@tg).
   Контант спрашивать максимум 2 раза, затем мягко предлагать менеджера.
6. В режиме `human` (открыт тикет handoff) бот в чате не отвечает, кроме
   сообщений «менеджер подключился/заявка закрыта».
7. Каждое сообщение клиента и все ответы сохраняются в историю чата (память).

## 7. Правила для AI-агента при разработке

- **Стек не менять** без обсуждения. Новые зависимости — только после вопроса
  «можно ли без них?».
- TypeScript strict. Типы располагать рядом с модулем; общий контракт — в
  `src/storage/types.ts`.
- Все тексты бота — на русском, идентификаторы кода — на английском,
  комментарии — на русском.
- Никаких секретов в коде/логах/git. Всё через `.env` (см. `config.ts`).
- Обработка ошибок обязательна: падение одного запроса не должно ронять
  процесс; LLM недоступен → фолбэк на шаблонный ответ.
- Definition of Done: `npm run build` проходит без ошибок, `npm run doctor`
  зелёный, сценарий проверен руками в Telegram.
- Коммиты: `feat:`, `fix:`, `docs:`, `refactor:` — коротко, по-русски можно.
- После значимых изменений обновлять раздел «План этапов» ниже (галочки).
